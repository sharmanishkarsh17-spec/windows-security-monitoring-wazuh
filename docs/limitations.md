# Limitations

## Overview

The project demonstrates an end-to-end Windows security monitoring and detection-engineering workflow using controlled validation activity and naturally occurring Windows telemetry.

The results should be interpreted within the scope of the local lab environment and the validation methods used.

## 1. Controlled Validation Environment

Testing was performed in a controlled Windows environment rather than a production enterprise network.

The validation demonstrates telemetry collection, detection logic, alert generation, and investigation workflows but does not represent production-scale SOC deployment.

## 2. Credential-Dumping Detection

The credential-access process detection was validated using controlled keyword-based process telemetry.

No actual credential-dumping operation or credential extraction was performed.

Therefore, the validation demonstrates the detection logic and telemetry path rather than successful detection of a real credential-dumping attack.

## 3. LSASS Access

Sysmon Event ID 10 telemetry targeting lsass.exe was observed and successfully processed by Wazuh.

Some LSASS access can be generated by legitimate Windows security software. Detection results therefore require contextual investigation to distinguish expected activity from suspicious behavior.

## 4. Credential-Store File Detection

The Sigma detection monitors browser and Windows credential-store-related file paths.

The Sysmon configuration used during validation monitored controlled file creation under C:\Temp\. This was used to validate the telemetry and Wazuh pipeline without modifying real credential-store files.

As a result, the validation confirms the FileCreate telemetry pipeline but does not demonstrate access to actual browser credential databases or Windows credential stores.

## 5. Correlation Detection

The repeated-failed-logon correlation rule was successfully validated for Sigma syntax and OpenSearch conversion.

The configured threshold of more than five matching events from the same source within five minutes was not positively observed during the available testing.

## 6. Event Interpretation

Individual security events do not automatically indicate malicious activity.

Events such as failed logons, LSASS access, process creation, file creation, and special-privilege assignments can have legitimate causes. Effective detection therefore requires investigation and contextual analysis.

## 7. Production Deployment

The project is a security monitoring and detection-engineering lab implementation.

It does not claim enterprise-scale deployment, production SOC operation, automated incident response, or complete coverage of Windows credential-access techniques.

## 8. Detection Coverage

The detection rules focus on selected authentication, credential-access, LSASS, credential-store, and privilege-related telemetry.

They are not intended to provide comprehensive coverage of all Windows attack techniques or all MITRE ATT&CK techniques.

## 9. Configuration Scope

The repository contains sanitized configuration examples rather than complete environment-specific deployment configurations.

Credentials, certificates, private keys, keystores, raw logs, and other sensitive environment-specific data are intentionally excluded.

## Conclusion

Despite these limitations, the project demonstrates practical detection-engineering concepts including Windows telemetry collection, Sysmon monitoring, Wazuh alerting, Sigma rule development, MITRE ATT&CK mapping, OpenSearch investigation, and controlled validation.
